# Sync v2 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Replace whole-domain-blob Firestore writes (the root cause of repeated data loss) with atomic per-record nested field-path updates, sharded into per-month documents.

**Architecture:** localStorage stays the offline-first source of truth and the app's React/localStorage shapes are unchanged. The sync layer is rewritten: each edit is diffed to the exact keys that changed, those keys are written as atomic Firestore `update({"entries.<key>": …})` field-path operations on a per-month document, and reads hydrate from a small set of month docs + one definitions doc. Last-write-wins per record via a `_t` timestamp. A one-time, non-destructive migration explodes the existing blob into the new shape.

**Tech Stack:** React 18, Vite, Firestore (compat SDK + REST fallback), Vitest. No new dependencies.

**Design doc:** `docs/plans/2026-05-28-sync-v2-design.md`

- **Run a single test file with:** `npx vitest run <path>` ; watch with `npx vitest <path>`. Full suite: `npm test`.
- **Commits:** small and frequent, one per task step group. Do NOT bump app version or deploy until Task 16. The repo's CLAUDE.md requires version bump + `npm run build && npm run deploy` on deploy — that happens once, at the end.
- **Do not touch** `src/App.jsx`, `src/hooks/useLocalStorage.js`, or any component's data shape. The only React-facing file that changes is `src/hooks/useSyncEngine.js` (Task 12), and its external return shape stays the same.
- **Isolation:** this work should run in a dedicated git worktree (see executing-plans / subagent-driven-development). Branch name suggestion: `sync-v2`.
- **Glossary:**
  - *map domain* — stored as `{ key: value }`: `entries`, `stackEntries`, `inputEntries`, `dailyNotes`.
  - *definition domain* — `symptoms`, `stackItems`, `inputItems` (arrays of `{id,…}` today), plus `pinnedSymptoms` (array) and `trackingMode` (scalar).
  - *record key* — for map domains a string beginning `YYYY-MM-DD` (e.g. `2026-05-28-flushing-morning`). The month id is its first 7 chars (`2026-05`).
  - *`_t`* — write time in ms (`Date.now()`), attached to each record for last-write-wins.

**Step 3 — Implement `src/sync/keyRouting.js`:**

```js
// Pure helpers mapping date-prefixed record keys to per-month buckets.
const DATE_PREFIX_RE = /^(\d{4}-\d{2})-\d{2}/;
export const MONTH_RE = /^\d{4}-\d{2}$/;

export function monthIdForKey(key) {
  if (typeof key !== 'string') return null;
  const m = key.match(DATE_PREFIX_RE);
  return m ? m[1] : null;
}

export function monthIdForDate(dateStr) {
  if (typeof dateStr !== 'string') return null;
  const m = dateStr.match(/^(\d{4}-\d{2})-\d{2}/);
  return m ? m[1] : null;
}

export function groupKeysByMonth(keys) {
  const out = {};
  for (const key of keys) {
    const month = monthIdForKey(key);
    if (!month) continue;
    (out[month] ||= []).push(key);
  }
  return out;
}
```

**Step 4 — Run green:** same command → PASS.

### Task 3: Change diff + `_t` stamping

**Files:**
- Create: `src/sync/changeDiff.js`
- Test: `src/sync/__tests__/changeDiff.test.js`

Given the previous synced view of a domain and the new local view, compute the
exact records that changed or were deleted, stamping changed records with `_t`.
This is the heart of "write only what changed." It generalizes the old
`_stampChanges` but also emits **deletions** (which the blob model never needed
to track explicitly).

**Step 1 — Write failing tests:**

```js
import { describe, it, expect } from 'vitest';
import { diffMapDomain } from '../changeDiff';

const T = 1000; // fixed clock

describe('diffMapDomain', () => {
  it('detects a new key as changed and stamps _t', () => {
    const { changed, deleted } = diffMapDomain(
      { 'k1': { severity: 1, _t: 1 } },                  // prev (last synced)
      { 'k1': { severity: 1, _t: 1 }, 'k2': { severity: 2 } }, // next (local)
      T);
    expect(deleted).toEqual([]);
    expect(changed).toEqual({ 'k2': { severity: 2, _t: T } });
  });

  it('detects a value change and restamps only that key', () => {
    const { changed, deleted } = diffMapDomain(
      { 'k1': { severity: 1, _t: 5 } },
      { 'k1': { severity: 3, _t: 5 } },
      T);
    expect(changed).toEqual({ 'k1': { severity: 3, _t: T } });
    expect(deleted).toEqual([]);
  });

  it('ignores _t-only differences (no real change → no write)', () => {
    const { changed, deleted } = diffMapDomain(
      { 'k1': { severity: 1, _t: 5 } },
      { 'k1': { severity: 1, _t: 9 } },
      T);
    expect(changed).toEqual({});
    expect(deleted).toEqual([]);
  });

  it('detects a deleted key', () => {
    const { changed, deleted } = diffMapDomain(
      { 'k1': { severity: 1, _t: 5 }, 'k2': { severity: 2, _t: 5 } },
      { 'k1': { severity: 1, _t: 5 } },
      T);
    expect(changed).toEqual({});
    expect(deleted).toEqual(['k2']);
  });
});
```

**Step 2 — Run red.**

**Step 3 — Implement `diffMapDomain(prev, next, now = Date.now())`:** compare by
value ignoring `_t` (reuse the `_equalIgnoringT` idea from the old engine —
move it here as a pure helper `equalIgnoringT`); changed keys get `{...value, _t: now}`;
keys in `prev` but not `next` go to `deleted`. Also implement and test
`diffIdMapDomain` for definition domains keyed by id (same logic; values are the
id-keyed objects). Export `equalIgnoringT`.

**Step 4 — Run green. Step 5 — Commit:** `feat(sync): change diff with deletion tracking and _t stamping`

> **Design note for the engineer (deletes over the listener):** because a month
> doc holds the authoritative map for that month, the listener should treat an
> incoming month doc as authoritative for that month's keys: `local[month-keys] =
> mergeMapByTime(localForThatMonth, incomingMonthMap)` **then** drop local keys
> for that month that are absent from the incoming map AND whose local `_t` is
> not newer than the doc's observed write. Simplest correct rule for LWW-single-
> user: a month doc snapshot replaces that month's slice of the domain, except
> for local keys with a strictly newer `_t` that haven't flushed yet. Cover this
> explicitly with a test in Task 10.

### Task 11: SyncEngineV2 — write path (diff → field updates → flush)

**Files:**
- Modify: `src/sync/SyncEngineV2.js`
- Test: `src/sync/__tests__/SyncEngineV2.write.test.js`

`notifyLocalChange(domain, data)`:
1. `diffMapDomain`/`diffIdMapDomain` against the shadow for that domain.
2. For map domains: `groupKeysByMonth` the changed+deleted keys; for each month
   build `{ updates: {"entries.<key>": val}, deletes: ["entries.<key>"] }` and
   enqueue a write to `months/<month>` via `fieldWriter`.
3. For definition domains: enqueue to `meta/definitions` with `"<domain>.<id>"`
   paths; `pinnedSymptoms`/`trackingMode` are whole-field writes (`"pinnedSymptoms"`,
   `"trackingMode"`).
4. Debounce (keep 500 ms) then flush each affected doc with one `update()`.
5. On flush success, update the shadow so the next diff is incremental.

**Tests:** single severity tap → exactly one `update({"entries.<key>":…})` on the
correct month doc, no other field touched; a delete → `deleteField()` on that
path; edits spanning two months → two doc writes; a hidden supplement
(`stackItems` active:false) → one `update({"stackItems.<id>":…})` and the value
is NOT reverted by a subsequent listener echo (regression for the v5.5.0
supplement-hide bug).

Commit `feat(sync): SyncEngineV2 granular write path`.

## Risk notes for the engineer

- **Clock skew:** LWW uses client `Date.now()`. Acceptable for single user; do
  not "fix" by introducing serverTimestamp into nested fields (awkward + breaks
  offline). Out of scope.
- **Do not delete the legacy blob doc** in any task. It is the last-resort backup.
- **Migrate from localStorage, never from the cloud blob** — localStorage is the
  freshest source on the migrating device.
- **Keep the 500 ms debounce.** It batches field paths into one write; it is not
  the source of the data loss (the blob rewrite was).
